# 路线图与行程海报 PRD

- 状态：待审核
- 关联：[计划约束](AGENTS.md) · [进度](progress.md)
- 前置调研：MapLibre v5 + OpenFreeMap、html-to-image 的能力与限制已核实；坐标数据基础已盘点（见 §5）。

## 1. 背景与目标

用户已经能在 App 内按日期查看行程安排，但看不到「整趟旅程在地图上怎么走」，也没有适合对外分享的图片产物。本功能交付两件事：

1. **应用内路线图**：把行程中有坐标的安排按时间顺序画在地图上，可浏览、可点选联动。
2. **行程海报**：把这些信息排成一张好看的图片，用户保存到相册后自行发朋友圈等外部渠道。

两个功能都只在客户端运行，不新增服务端接口，不上传任何行程数据。

## 2. 用户与使用场景

- 出行前：确认路线顺序是否合理（「要不要把大阪放在东京前面」）。
- 出行中：看当前位置与接下来要去的站点的大致方位（不替代导航）。
- 出行后 / 出行前：生成一张海报发朋友圈，让别人看到「我去了哪、走了多长的路线」。

不面向：实时导航、路况、公共交通换乘查询（仍走外部地图链接）。

## 3. 范围

### v1 包含

- 路线图全屏视图：按时间顺序连线、按键选日/按站点高亮、点击站点打开安排详情。
- 航班画球面大圆弧线，其余安排画直线；起点与终点使用不同颜色区分。
- 缺坐标安排的处理与提示（不静默丢弃，也不阻塞地图）。
- 海报：1 套 3:4 模板，客户端生成 1080×1440 PNG，保存 / 系统分享。
- 海报中的地图直接取自 MapLibre 实例截图，与 App 内地图同源。
- iOS 15.5 Safari 与 320px 宽度可用；底图使用 OpenFreeMap 公共实例（无需 key）。

### v1 不包含（记录为后续）

- 缺坐标安排的「一键批量补齐坐标」（复用 `/api/places`，v2 评估）。
- Geoapify Routing 真实道路路径（自驾/火车仍为虚线直线）。
- 海报二维码（依赖已发布到市场的公开分享）、9:16 故事尺寸、多套模板。
- 底图源可视化切换 / 自托管配置界面（代码层保留常量与换源能力即可）。
- Worker / 服务端出图（satori）、OG 分享图。

## 4. 术语

- **站点（stop）**：一条有坐标的安排在地图上的落点。
- **路线（route）**：站点按时间顺序连接得到的折线（含航班弧段）。
- **海报（poster）**：客户端生成的位图，用于外部分享。
- **公开快照**：市场分享使用的字段白名单快照（`shared/market.ts`），海报不读取它的私人部分。

## 5. 现状与数据基础（已核实）

- 数据模型：`shared/places.ts` 的 `placeSchema` 含 `latitude` / `longitude` / `countryCode`；`TripEvent.location` 与交通类的 `departureLocation` 为可选 Place。**没有 order 字段，天然按 `start` 时间排序即为路线顺序。**
- 地理编码：Worker 已有 `GET /api/places?q=`（Geoapify，密钥在 Worker Secret），可作 v2 补坐标的来源。
- 分享体系：公开攻略市场（`public_itineraries` + 快照 + 口令）已存在，海报未来可挂二维码指向 `?share=:id`。
- 部署形态：Next.js `output: "export"`，服务端逻辑全在 Worker；当前**没有任何地图库与图片生成依赖**。
- 坐标覆盖率（本地预览库样本）：7 条安排中 5 条有 `location`，2 条为空；航班另带 `departureLocation`。样本过小，仅用于确认「必须处理缺坐标」，不代表生产分布。
- 导航结构：底部五项（现在 / 行程 / 资料 / 账本 / 我的）保持不动。

## 6. 功能一：应用内路线图

### 6.1 入口

- 位置：完整行程页标题行，现有「添加安排」加号左侧增加一个地图图标按钮，`aria-label="查看路线图"`。
- 不新增底部导航项，不新增独立操作行，不改变现有标题 / 筛选 / 内容布局。
- 打开方式：全屏 `Sheet`（沿用 `web/src/components/ui.tsx` 的统一弹窗），顶部标题「行程路线」，右上角「生成海报」入口；可下滑 / 返回关闭。

### 6.2 路线数据构建（纯函数，可单测）

- 输入 `TripEvent[]`，输出站点序列与线段集合。
- 顺序：按 `start` 升序；同刻按 `dateEnd` / 创建顺序稳定排序。
- 取点优先级：`event.location` 优先；交通类若首站缺 `location` 但有 `departureLocation`，可作为该段起点。
- 去重：连续相同坐标（同一地点多安排）合并为一个站点，保留最早时间与多条安排引用。
- 航班段用球面插值（great-circle）生成折线点，其余用两点的直线段。
- 输出同时保留「无坐标安排」列表（标题 + 时间 + 原因），供提示与点选补全。
- 该模块不依赖 maplibre，只产出 GeoJSON 与站点元数据，便于单元测试。

### 6.3 地图与底图

- 库：`maplibre-gl` v5（当前 5.24.0），**客户端动态 `import()`**，仅在打开路线图 / 生成海报时加载，不进首屏包。
- 底图：OpenFreeMap 公共实例，样式 URL 作为集中常量（预留换源 / 自托管）。
- 强制保留 attribution（`© OpenStreetMap contributors` / MapLibre），不可移除。
- 初始视角 `fitBounds` 覆盖全部站点；单站点时使用固定缩放级别。

### 6.4 绘制与交互

- 路线：GeoJSON `LineString` + line layer；起点与终点用不同颜色 / 图标区分。
- 站点：`Marker` 显示序号与标题（移动端精简为序号圆点，选中时展开标题）。
- 按日筛选：复用完整行程的日期语义，选中某天时高亮该天站点与线段，其余降透明度。
- 点选：点击站点或（从完整行程某天进入时）默认聚焦该天；站点详情复用现有 `EventDetail` 打开。
- 手势：地图自身支持缩放 / 平移；页面滚动与地图手势不冲突（全屏视图内地图占满可用区域）。

### 6.5 缺坐标处理

- 地图仍按「有坐标的站点」连线，不伪造坐标、不静默丢弃。
- 视图内提供一行可展开提示：「N 项安排没有坐标，未显示在地图上」，展开列出这些安排并可点开详情。
- v1 不自动地理编码（避免误匹配与额外请求）；补齐仍走已有安排编辑流程。

### 6.6 空态与降级

- 全部安排都无坐标：地图区域替换为 `EmptyState`，提示「安排还没有地点，添加地点后可以看到路线」，并提供进入完整行程的入口。
- maplibre 加载失败 / WebGL 不可用：显示错误说明 + 站点的文本路线列表（按时间的起终点 / 地名），不显示空白画布。
- 网络失败：底图加载失败时保留已有站点列表文本，提示可重试。

## 7. 功能二：行程海报

### 7.1 入口

- 主入口：路线图视图右上角「生成海报」。
- 次入口：「我的行程 → 具体行程管理 → 分享我的行程攻略」区域，新增一行同款按钮「生成行程海报」。两个入口打开同一套全屏预览。

### 7.2 内容与隐私（白名单）

海报可能被公开，默认只包含：

- 行程名称（用户可改的覆盖名优先，默认原行程名）。
- 日期范围、天数、目的地、安排数量。
- 地图（路线）与起点 / 终点地名、代表性站点的天数标注。
- 底图署名 `© OpenStreetMap contributors`。

**不包含**：同行成员姓名与头像、账本 / 金额、旅行资料、电话、预订编号、私人备注、准备清单。海报纯客户端生成，不上传、不落 R2。

成员信息是否可选展示留待 §15 确认；v1 一律不展示。

### 7.3 模板与排版

- 尺寸：设计稿 360×480 CSS px，`pixelRatio: 3` 输出 1080×1440 PNG（3:4，朋友圈信息流比例友好）。
- 结构：顶部行程名 + 日期；中部地图（约半屏）；下半部路线起终点与关键站点 / 天数列；底部目的地、天数、安排数量与署名。
- 视觉遵循 `DESIGN.md`：纸张背景、淡紫票券质感、圆角、可复用 `TravelSticker` 贴纸与票券缺口 / 虚线分隔。具体排版在实现阶段出稿后再冻结。
- 字体只使用系统字体，避免嵌入字体（html-to-image 设置 `skipFonts` / 提供 `fontEmbedCSS`），规避 WebKit 字体嵌入坑。
- 地图截图与图片均转 data URI，避免跨域污染 canvas。

### 7.4 地图来源

- 使用一个**隐藏的独立 MapLibre 实例**：`preserveDrawingBuffer: true`，按海报比例 `fitBounds`，`setPixelRatio(2)` 提清晰度，`idle` 后 `getCanvas().toDataURL()`。
- 不复用可见地图实例（比例与状态不同），生成完成 / 关闭预览后销毁该实例，释放内存。
- 若地图截图失败，海报降级为无地图版式仍可生成（不整体失败）。

### 7.5 生成、保存与分享

- 生成：`html-to-image` 的 `toPng()`，生成期间按钮进入 loading 并防重复点击，展示进度文案。
- 分享：优先 `navigator.share({ files: [file] })`（用 `navigator.canShare` 探测）；不支持时回退为 `a[download]` 保存 PNG。
- 文案明确说明现实约束：微信不支持网页直发朋友圈，用户保存 / 系统分享后自行发布。
- 成功后使用全局 toast（`useToast`），不在预览内部重复成功文案。

### 7.6 失败与重试

- 地图瓦片未加载完就截图 → 等待 `idle`（含超时兜底），超时则用无地图版式。
- `toPng` 失败 → 显示就近错误与「重试」，保留预览状态。
- 关闭预览时清理隐藏地图实例、临时 blob 与 data URI，避免内存 / 对象 URL 泄漏。

## 8. 数据与接口

- **不新增 Worker 接口，不新增数据库迁移。** 数据全部来自已加载的 `TripData`。
- 地图底图与瓦片为第三方静态资源（OpenFreeMap），不经 Worker。
- Geoapify 仅保留现有服务端搜索能力；前端不得接触 `GEOAPIFY_API_KEY`。
- 新增依赖：`maplibre-gl@^5.24.0`（运行时，动态加载）、`html-to-image@^1.11.13`（运行时）。两条都需通过 `scripts/check-browser-support.mjs` 校验产物语法。

## 9. 兼容性、性能与安全

- **最低浏览器红线**：`safari >= 15.4`（实际最低 iOS 15.5）。maplibre 锁定 v5；升级 v6 前必须重新跑 `npm run check:browser` 确认无 class static block。
- 动态 import 使地图与出图代码不进入首屏；关闭视图后不残留地图实例。
- 320px 宽度无横向溢出；地图容器与海报预览按宽度自适应。
- 海报生成全程在本地，不发送网络请求携带行程内容；不得把任何行程数据写入日志。
- 底图 attribution 与 `.local` 截图产物遵循既有忽略约定。

## 10. 设计规范落地

- 入口遵循「不新增顶部行程信息 / 不新增独立操作行」；新增能力只用标题右侧带 `aria-label` 的图标按钮。
- 弹窗统一 `Sheet` / `SheetForm` / `SheetFooter`，标题与底部按钮固定、中间滚动。
- 空态统一 `EmptyState`，并区分「首次使用」与「筛选无结果」。
- 危险操作（本功能暂无删除）一律红色 + 二次确认。
- 完整行程页原布局不动；路线图 / 海报均为覆盖层。

## 11. 技术选型结论

| 项 | 选择 | 理由 |
| --- | --- | --- |
| 地图渲染 | `maplibre-gl` v5 + OpenFreeMap | 开源、无 key、免费；v5 产物满足 iOS 15.5 |
| 地图集成方式 | 原生 API（Marker / GeoJSON layer） | 少一层 react 绑定，降低兼容风险 |
| 海报出图 | DOM 模板 + `html-to-image` | 复用 Tailwind 设计系统，静态导出架构下零服务端成本 |
| 海报地图 | 隐藏 MapLibre 实例截图 | 与 App 内地图同源、所见即所得 |
| 路线计算 | 自有纯函数（直线 + 大圆弧） | 不引入 turf，可单测 |

## 12. 验收标准

1. 完整行程页可打开全屏路线图；有坐标的安排按时间连线，航班为弧线，起终点可区分。
2. 点击站点能打开对应安排详情；缺坐标安排有明确提示且可点开，不被静默丢弃。
3. 海报可从地图视图与行程管理两处生成，输出 1080×1440 PNG；含地图、行程名、日期、起终点与署名。
4. 保存 / 系统分享可用，不支持时回退下载；生成过程有进度、失败可重试。
5. 海报与界面均不出现成员、账本、资料、电话、预订编号、私人备注。
6. `npm run typecheck`、`npm test`、`npm run build`（含 `check:browser`）通过；新增路线构建单测通过。
7. Playwright 在 Chromium 与 WebKit 验证：打开路线图、生成海报、320px 无横向溢出、无控制台异常。
8. 只提交到本地分支，不推送、不部署。

## 13. 分期

1. **阶段 02 路线图**：路线构建纯函数 + 单测 → 全屏视图 + MapLibre v5/OpenFreeMap → 站点联动、缺坐标提示、空态 / 降级。
2. **阶段 03 海报**：模板与隐藏地图截图 → html-to-image 出图 → 保存 / 分享 → 失败重试与清理。
3. **v2**（另立计划）：缺坐标批量补齐、真实路径、二维码、多尺寸 / 多模板、底图源切换。

## 14. 风险与处理

| 风险 | 影响 | 处理 |
| --- | --- | --- |
| OpenFreeMap 无 SLA、国内访问偏慢 | 地图加载慢或失败 | 样式 URL 集中常量、保留换源 / 自托管；失败降级为文本路线 |
| maplibre v6 产物含 iOS 15.5 不支持语法 | 构建门禁失败 / 线上白屏 | 锁 v5，升级前重跑 `check:browser` |
| 坐标覆盖率低 | 路线不完整 | 明示缺坐标安排，v2 再补 |
| WebGL 不可用 / 截图失败 | 地图或海报异常 | 降级为文本路线 / 无地图海报 |
| html-to-image 在 WebKit 的字体 / 图片坑 | 海报空白或错位 | 系统字体 + `skipFonts`、图片转 data URI、WebKit 实测 |
